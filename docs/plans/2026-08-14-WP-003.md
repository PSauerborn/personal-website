## Objective

Deliver the public frontend of psauerborn.dev: a server-side rendered Next.js
(App Router) application that presents the site owner's CV, a contact form, the
agentic development workflow, the project index, and the blog, consuming the
SPEC-002 API defined in `docs/openapi.yaml`. All SEO-critical content is
fetched in Server Components; exactly four **feature/island** client components
exist under `web/components/{home,blog}/` (framework- and vendor-required
`"use client"` directives in `web/app/error.tsx` and `web/components/ui/**`
are excluded from that count — see PC-6). The application is served on port
9000 (the API's CORS allowlist origin), built by a two-stage Node 22
Dockerfile, and added to `docker-compose.yaml` as a `web` service.

Every UI task implements the user-selected design **DES-001 Option 1
("Broadsheet")** — a single centered 1024px column on every route, hairline
rules instead of cards, three text colours and two weights, sticky glass
header. Downstream agents must read `docs/plans/designs/DES-001/DES-001-option-1.md`
and its HTML mockup before authoring any component; do not substitute an
alternative visual direction.

## Background

- `api/` (SPEC-002) is complete and serves every endpoint in
  `docs/openapi.yaml`. SPEC-003 is UI-only: no API, data model, or schema
  changes.
- `docs/plans/designs/DS-004-CV/`, `DS-004-BLOG/`, and `DS-004-AGENTS/`
  contain working `.tsx` prototypes built against mock data. Per SPEC-003 §4
  and explicit user direction they are **visual reference only** — every
  component and stylesheet is re-authored in `web/` against the OpenAPI types.
  Do not copy `cv-section-explorer.tsx`, `blog-index.tsx`, `cv-data.ts`,
  `article-data.ts`, or `theme.css` into `web/`.
- Design tokens originate from
  `docs/specs/external-docs/stylesheets/app.scss` and are re-derived into
  `web/app/globals.css` / the Tailwind theme.
- The repository has an established lint convention: `.pre-commit-config.yaml`
  runs `make -C api lint` gated on `files: ^api/`. `web/` follows the same
  pattern.
- The risk plan (`docs/plans/risk/WP-003/WP-003-risk-plan.md`) is
  user-approved. Its plan-level defects (RISK-001, RISK-002, RISK-004,

### User decisions (deliberate deviations — take precedence over spec text)

These were resolved with the user during the spec-review,
scale-determination, and risk-approval gates. Record them as intentional;
reviewers must not flag them as drift.

1. **Application root**: the app lives in `web/` at the repository root
   (sibling to `api/`). All SPEC-003 §6.1 segment paths are relative to
   `web/` (homepage segment is `web/app/page.tsx`).
2. **Standards waiver — exact boundary (RISK-019)**: waived for `web/` by
   explicit user grant, because SPEC-003 mandates Next.js App Router +
   TypeScript + Tailwind + shadcn/ui: `[JS-002]`, `[JS-003]`, `[JS-004]`,
   `[JS-007]` (`/etc/coding-standards/javascript/GENERAL.md`). **Still in
   force**: `[JS-001]`, `[JS-005]`, `[JS-006]`, `[JS-008]`–`[JS-014]`, all
   `[JS-DOCKER-*]` and `[DOCKER-*]`, `[GEN-*]`, and `[MAKE-001]`. The
   `[JS-008]` (camelCase filename) deviation is limited to App Router
   reserved files (`page.tsx`, `layout.tsx`, `not-found.tsx`, `error.tsx`)
   and `web/components/ui/**`. This exact boundary must be recorded in
   `web/README.md` (Task 1) and cited in every `web/` task; the waiver must
   not be read more broadly than granted.
3. **No UI acceptance harness**: `acceptance/` holds only `.feature` files —
   there is no godog runner, step definitions, or `go.mod`, and building a
   browser-driven harness is out of scope. `@ui @spec-003` scenarios are
   specification only. Implementation is verified by build, lint, type-check,
   and component/unit tests.
4. **REQ-1.6 relaxed to four client components**: contact form, blog index
   search filter, comments section, **and the homepage CV section explorer**
   (retains client-side skill filtering per the accepted DS-004-CV behaviour).
   CV data is still fetched server-side, so REQ-1.5 and SEO markup are
   unaffected.
5. **Agents page spec content**: REQ-3.4 renders spec document content on
   demand via `GET /v1/agents/specs/{id}/{document_id}` in addition to
   `GET /v1/agents/specs/list` — one API dependency beyond SPEC-003 §6.1's
   table for `/agents`. DES-001 Option 1 uses native `<details>` elements, so
   the content is in the server payload with zero client JS.
6. **Personal details (REQ-2.1)**: `GET /v1/cv` returns only
   skills/experience/education. Real personal details are **committed** to
   `web/lib/site-config.ts` (user chose committed real values over env vars).
   The name is **Pascal Sauerborn** and the email is
   `pascal.sauerborn@gmail.com`. The phone number, headline summary, and the
   REQ-3.5 agents-repository GitHub URL are **supplied by the user directly**
   — the CV PDF at `docs/specs/external-docs/PSauerborn CV.pdf` cannot be
   read in this environment (no PDF tooling installed) and must not be used
   as a source. If any of these values has not been supplied when the task
   needs it, that is a **hard blocker to escalate**, not a detail to invent;
   the realistic-looking placeholders in `DES-001-option-1.html` must never
   be committed.
7. **Design artifacts re-authored**: see Background — everything, including
   stylesheets, is re-authored; tokens re-derived from `app.scss`.
8. **docker-compose extension**: a `web` service is added to
   `docker-compose.yaml` serving on port 9000 with `API_BASE_URL` pointing at
   the internal `api` service — a deliberate extension beyond SPEC-003 §3.2's
   "deployment out of scope" boundary.
9. **Accessibility token fix**: `--color-text-tertiary: hsl(220 5% 42%)` in
   `docs/specs/external-docs/stylesheets/app.scss` fails WCAG AA (~3.6:1).
   DES-001 corrects it to `hsl(220 5% 50%)` (~4.6:1). Apply the correction to
   the token source file **and** the derived `web/` tokens.
10. **Acceptance scenario authoring (RISK-024 mitigation)**: the user has
    explicitly directed that the new `@ui @spec-003` scenarios for the
    agents, projects, blog index, and blog post pages **be authored into the
    existing feature files as part of this work plan** (Task 17). This
    supersedes the earlier position that no task touches
    `acceptance/features/`. The additions are strictly **append-only** and
    the scenarios remain **specification only** per decision 3 — they are not
    executable (no godog runner, step definitions, or `go.mod` under
    `acceptance/`), which is the user-accepted position from the requirements
    gate.

## Failure Modes

- [ ] `CVSkills` empty object → filter bar suppressed, timelines intact
- [ ] `end_date: null` on experience/education → "Current"/ongoing rendering,
      never "null" or Invalid Date
- [ ] `github_link: null` on a project → GitHub line omitted entirely
- [ ] Comment `author: null` → italic "Anonymous", never an empty byline
- [ ] Empty listings (projects, articles, comments, specs, agents) → DES-001
      empty states; blog search bar suppressed when no articles exist
- [ ] Unknown `article_id` (absent from listing) or 404 from content endpoint
      → the API client's distinct 404 signal → `not-found.tsx`; any other
      failure → `error.tsx` (never a retry-forever error boundary on a true
      404)
- [ ] Any server-side API failure (5xx, network) → `error.tsx` with reset
- [ ] Malicious HTML/script in article markdown → sanitized, inert (stored
      XSS vector otherwise)
- [ ] Malicious HTML/script in a **comment body** (attacker-writable via the
      unauthenticated comment POST) → rendered as plain text children with
      `white-space: pre-wrap`, inert
- [ ] Malicious HTML/script in **spec document content** on `/agents` →
      preformatted text or sanitized pipeline, inert
- [ ] Content endpoints parsed as JSON by mistake → unreachable by
      construction: the content modules can only call the client's text
      reader (`binary/octet-stream`)
- [ ] Hung API socket → every request carries `AbortSignal.timeout`; no
      unbounded awaits in Server Components
- [ ] Browser calls issued from an origin other than `http://localhost:9000`
      (e.g. dev server on 3000) → CORS rejection; port 9000 is mandatory in
      dev and container
- [ ] `NEXT_PUBLIC_API_BASE_URL` set only as a runtime `environment:` entry →
      silently ignored by the already-built bundle; must be a compose
      `build.arg` with `ARG`/`ENV` in the builder stage, verified by grepping
      built client chunks
- [ ] `.next/standalone` missing at image build → `output: 'standalone'` set
      in Task 1's `next.config.ts`; `.next/static` and `public/` copied
      alongside
- [ ] Client/server render divergence over `hidden` filtering or date
      formatting → hydration mismatch; format dates deterministically
      (locale/timezone-stable)
- [ ] Contact/comment POST failure (400 or network) → inline error, user
      input preserved; success state keeps email visible (contact) / clears
      composer (comments)
- [ ] Failed or hanging per-document spec content fetch on `/agents` →
      `Promise.allSettled` + per-request timeout; the failed document
      degrades to an inline "content unavailable" disclosure, the rest of
      the page renders
- [ ] Phone number, headline summary, or agents-repository URL not yet
      supplied by the user → **escalate (hard blocker)**; never invent values
      or copy the placeholders from `DES-001-option-1.html`
- [ ] Mutable-tag base images in `web/Dockerfile` → pin immutably
- [ ] Any modification, renumbering, or deletion of an existing scenario (or
      any touch of an `@api` scenario) by Task 17 → forbidden; additions are
      append-only

## Reference Contracts

**API** (`docs/openapi.yaml` is authoritative; all under `/v1`, JSON except
the two content endpoints):

| Endpoint | Response / notes |
| --- | --- |
| `GET /v1/cv` | `CVResponse`: `skills` (map category → string[]), `experience[]` (`id, organization, job_title, start_date, end_date?, description, tech_stack[], responsibilities[]`), `education[]` (`id, institution, certificate, start_date, end_date?`); most recent first; empty collections, never null |
| `GET /v1/agents/list` | `AgentListResponse.agents[]`: `id, name, description, inputs{}, outputs{}` (empty objects, never null) |
| `GET /v1/agents/specs/list` | `SpecListResponse.specs[]`: `id, display_name, description, documents[]` (`document_id, filename, document_type: spec\|acceptance\|other`); `documents` may be empty |
| `GET /v1/agents/specs/{id}/{document_id}` | Raw bytes, `binary/octet-stream` — text reader only; 404 envelope for missing/restricted |
| `GET /v1/articles/list` | `ArticleListResponse.articles[]`: `id, title, description, author, topics[], created_at` — never content or comments |
| `GET /v1/articles/{article_id}/content` | Raw markdown bytes, `binary/octet-stream` (spec §4.7's "octet-stream/binary" is wrong) — text reader only; 404 envelope |
| `GET /v1/articles/{article_id}/comments` | `{article_id, comments[]}`: `author` (nullable), `comment`, `created_at`; **oldest first**; 404 for hidden/unknown article |
| `POST /v1/articles/{article_id}/comment` | Body `{author?, comment}` → 201 `{comment_id}`; 400 `Error` on empty comment; 404 unknown article |
| `POST /v1/messages` | Body `{email, name, organization?, message}` → 201 `{message_id}`; 400 `Error` names offending field |
| `GET /v1/projects/list` | `ProjectListResponse.projects[]`: `id, name, description, primary_link, github_link` (nullable) |

- **Error envelope** (400/404/500): `{error: "Bad Request"|"Not Found"|
  "Internal Server Error", details: string}`. The client surfaces 404 as a
  distinct signal (dedicated error type or discriminated result).
- **CORS** (`api/router.go`): allowed origins `http://localhost:9000`,
  `https://psauerborn.dev`, `https://dev.psauerborn.dev`; methods GET, POST,
  PATCH, PUT, DELETE, OPTIONS; headers Content-Type, Accept, Accept-Language,
  Content-Language. The allowlist constrains the origin the **frontend** is
  served from — spec §6.3's claim that `NEXT_PUBLIC_API_BASE_URL` must be in
  the allowlist is incorrect.
- **Ports**: web listens on 9000 (dev and container — CORS-mandated).
  `api/config.yaml` defaults the API to 10000, but compose overrides
  `LISTEN_PORT: 8080` and publishes `${API_PORT:-8080}:8080`. In compose:
  `API_BASE_URL=http://api:8080` (service DNS, runtime env),
  `NEXT_PUBLIC_API_BASE_URL=http://localhost:8080` (compose `build.arg`,
  inlined at image build).
- **Env vars** (spec §6.3, with build/runtime semantics per RISK-001):
  `API_BASE_URL` (Server Components, internal address, **runtime**);
  `NEXT_PUBLIC_API_BASE_URL` (client components, browser-resolvable address,

  environment entry has no effect on a built image). Both in
  `web/.env.example` with the semantics documented there and in
