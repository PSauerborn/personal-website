Agentic development

The pipeline that built this site, documented in full

A spec goes in; an orchestrator delegates each stage to a specialist subagent and stops for approval at defined checkpoints; a reviewed, documented changeset comes out. Below: the nine stages, the thirteen agents, and the specs they were pointed at.

Workflow

The orchestrator decides what to do and where; each subagent decides how. Two markers matter when reading the run: a stop is a checkpoint that waits for the user, and a conditional stage only runs when it applies.

Agent catalogue

Every agent owns one responsibility, carries only the context that responsibility needs, and returns a typed response — completed, or blocked with a reason. Nothing here is a general assistant.

Specs

The specs the pipeline was pointed at. Each requirement traces to a tagged Gherkin scenario; the tag, not the file, is the unit of ownership, so a single feature file can serve several specs at once.

Continuous integration

Where the acceptance criteria actually execute. The suite runs against a live Postgres service on every pull request, so a criterion is either passing in CI or it is not met.
